# Leið SEO and social preview audit

Checked 2026-10-27 against https://www.layth.space/ and the current repository.
Audience: people looking for a browser music instrument or transit sonification.
Goal: accurate search identity and working shared-link previews.

## Verified findings and local fixes

| Finding | Evidence | Local change |
| --- | --- | --- |
| Critical: production canonical, og:url, og:image and twitter:image point to localhost:3000 | Metadata read from the deployed homepage in Chromium | Central public-origin fallback is now https://www.layth.space |
| robots.txt advertises localhost and has no sitemap | Deployed robots.txt read in Chromium | Uses the same public origin and advertises /sitemap.xml |
| No sitemap implementation | Repository audit | Added public pages; optional MCP guides follow their existing visibility flag |
| Secondary pages inherit homepage social titles and URLs | Repository metadata audit | Page-specific OG/Twitter metadata, including explicit image references |
| MCP sign-in and consent inherit index permissions | Repository metadata audit | Scoped noindex metadata for /mcp pages |

The deployed /opengraph-image renders a readable 1200×630 PNG, with the Leið name,
transit-line motif and product description. Its design does not need replacement.
The existing generator declares image dimensions, type and alt text; Twitter uses
the same artwork and summary_large_image.

## Remaining improvements and limits

- The homepage serves a loading screen before the client-only DAW loads. Add visible,
  server-rendered introductory copy and a guide link as a separate product/UI change.
  Google can render JavaScript, but recommends server rendering or prerendering for
  accessibility to crawlers: [Google JavaScript SEO guidance](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics).
- No JSON-LD was found. This is optional descriptive markup, not an indexing blocker.
- Raw command-line requests received Vercel security challenges (429), while normal
  Chromium navigation succeeded. This does not establish whether verified Googlebot
  or social-preview crawlers are challenged. Check actual crawler access in Vercel
  and Search Console if previews or crawling still fail after deployment.
- Index coverage, rankings, real-user Core Web Vitals and platform-cached social cards
  were not verified. No Search Console account data was accessed.
- Social image field requirements checked against the [Open Graph protocol](https://ogp.me/).

## Validation and release follow-up

Production build passed with NEXT_PUBLIC_APP_URL=https://www.layth.space. Generated
HTML was checked for correct canonical/OG/image origins on all 11 page routes,
page-specific OG URLs, MCP noindex, sitemap entries and the robots sitemap reference.

Changes are local, not deployed. Set NEXT_PUBLIC_APP_URL=https://www.layth.space
in the production environment; the code also falls back to that origin when absent.
After deploying, inspect the public metadata again and submit /sitemap.xml in
Search Console. Success means the emitted canonical and social image URLs resolve
on the public domain and the sitemap is fetchable; this alone cannot prove rankings
or traffic improvement. Frontend owns the remaining homepage-content work.
